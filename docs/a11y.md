# Accessibility Audit Notes

## Axe Runtime Checks
- `@axe-core/react` now auto-loads in development (client providers). Violations print to the browser console every second while navigating the app.
- The hook is disabled in production and guarded against double-registration in React strict-mode.

## Landmarks & Skip Navigation
- Global skip link (`Skip to main content`) lives at the top of `app/layout.tsx` and focuses `#main-content`.
- All major views (dashboard layout, sign-in) expose a `<main id="main-content" tabindex="-1">` region so screen readers land on the primary content immediately.

## Navigation Improvements
- `TopNav` and `AppSidebar` pass `aria-current="page"` on the active route, with high contrast active states.
- Sidebar anchors respect hash fragments by normalising the href, keeping the correct item highlighted when viewing deep links.

## Focus & Contrast
- Updated focus ring/active colour tokens stay inside our Tailwind theme and meet WCAG 2.2 AA contrast (brand 500 background vs white text).
- Skip link uses a 3px dual outline to maintain visibility on both light/dark backgrounds.

## Manual Audit Checklist
1. Keyboard tab-cycling hits skip link first, then main landmarks, and never traps focus.
2. Screen reader (VoiceOver/NVDA) announces “Primary navigation” for the sidebar and “Global” for the top nav.
3. Run browser DevTools > Lighthouse > Accessibility – expect 100 after fixes.

## Follow-ups
- If new routes are added, ensure they render a `main#main-content` region or re-use the dashboard layout.
- Keep an eye on brand palette adjustments; verify contrast with tools like Stark or the WCAG Contrast Checker when tokens change.
