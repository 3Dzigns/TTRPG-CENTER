# BUG-035 — Selective Ingestion Hanging on Pass A

**Reported By:** System Monitoring
**Date:** 2025-09-25
**Environment:** Ingest Service Pipeline, DEV/TEST/PROD

---

## Description
Selective ingestion processes hang indefinitely during **Pass A: TOC parsing and metadata extraction** at timestamp `[2025-09-25T12:16:42.182843]`. The ingestion pipeline becomes unresponsive when processing certain PDF files, requiring manual intervention to restart the service.

**Technical Details:**
- **Hang Point**: `src_common/toc_parser.py` during `page.extract_text()` operations
- **Impact**: Complete pipeline halt, preventing all PDF processing
- **Trigger**: Complex or scanned PDF documents that cause text extraction to block indefinitely

---

## Steps to Reproduce
1. Upload a complex PDF (large file, scanned content, or corrupt formatting) to ingestion pipeline
2. Monitor ingestion logs for Pass A execution
3. **Observed**: Process hangs at "Pass A: TOC parsing and metadata extraction"
4. **Expected**: Pass A should complete within reasonable timeframe (< 2 minutes)

---

## Expected Behavior
- Pass A should complete within 2 minutes regardless of PDF complexity
- Problematic PDFs should be processed with partial extraction rather than hanging
- Pipeline should continue processing other PDFs in queue
- Clear error messages should indicate when extraction issues occur

---

## Actual Behavior
- Process hangs indefinitely on `pypdf.PdfReader.pages[n].extract_text()` calls
- No timeout protection for text extraction operations
- Entire pipeline becomes unresponsive
- No error recovery or fallback mechanisms

---

## Impact
- **Critical**: Blocks entire ingestion pipeline
- Prevents processing of any new PDF uploads
- Requires manual service restart to recover
- Impacts downstream phases that depend on ingested content
- Violates Phase 1 requirements for reliable ingestion processing

---

## Root Cause Analysis

**Primary Issues Identified:**

1. **Blocking Text Extraction**
   - **Problem**: `pypdf.PdfReader.pages[n].extract_text()` can hang indefinitely
   - **Cause**: Complex PDFs, scanned documents, or corrupt formatting trigger blocking operations
   - **Location**: `toc_parser.py:139`, `toc_parser.py:177`, `toc_parser.py:260`

2. **Missing Timeout Protection**
   - **Problem**: No timeout mechanisms for PDF processing operations
   - **Cause**: Sequential processing without time bounds or interrupt capability
   - **Result**: Infinite wait states with no recovery path

3. **No Circuit Breaker Protection**
   - **Problem**: PDF processing operations lack failure protection patterns
   - **Cause**: Circuit breaker infrastructure exists but not applied to PDF operations
   - **Result**: Repeated hangs on same problematic files

**Technical Root Cause:**
The ToC parser processes PDFs sequentially without timeout protection or error isolation. When `extract_text()` encounters problematic content, it blocks the entire thread indefinitely with no recovery mechanism.

## Solution Implementation

**1. Timeout-Protected Text Extraction**
```python
import concurrent.futures
import threading

def extract_text_with_timeout(page, timeout_seconds=10):
    """Extract text with timeout protection"""
    with concurrent.futures.ThreadPoolExecutor() as executor:
        future = executor.submit(page.extract_text)
        try:
            return future.result(timeout=timeout_seconds)
        except concurrent.futures.TimeoutError:
            logger.warning(f"Text extraction timed out after {timeout_seconds}s")
            return ""  # Return empty string for timeout cases
```

**2. Circuit Breaker Integration**
