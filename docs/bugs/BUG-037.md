# BUG-037: Upload Management Drag-and-Drop and Browse Button Non-Functional

**Status:** Active
**Priority:** High
**Component:** Admin UI - Upload Management
**Created:** 2025-09-27
**Environment:** Development (Containerized Monolithic App)

## Summary

Upload Management functionality is completely broken in the restored monolithic application. Both drag-and-drop file upload and the "Select PDF Files" browse button are non-functional, preventing users from uploading files for ingestion.

## Symptoms

1. **Drag-and-Drop Failure**
   - Files can be dragged into the upload area
   - Visual feedback works (drag overlay appears)
   - Upload progress bar briefly appears but fails
   - No files appear in the uploads list

2. **Browse Button Failure**
   - "Select PDF Files" button opens file picker correctly
   - Files can be selected
   - Upload attempts but fails silently
   - No error messages shown to user

3. **Backend Symptoms**
   - Upload API endpoints return errors
   - Files not saved to expected directory
   - Upload directory mismatch between frontend expectations and backend reality

## Root Cause Analysis

### Investigation Results

**Frontend (Working Correctly):**
- ✅ AdminUtils properly defined in base.html
- ✅ Event handlers for drag-drop and browse button correctly attached
- ✅ JavaScript makes POST requests to `/api/uploads?env=dev` with proper FormData
- ✅ File validation and UI feedback mechanisms functional
- ✅ Drag-and-drop event handlers respond correctly

**Backend (Root Cause):**
- ❌ Upload directory path mismatch
- ❌ `_uploads_dir()` function returns `/data/uploads` (hardcoded fallback)
- ❌ Container expects uploads at `/app/env/dev/uploads` (mounted volume)
- ❌ Missing `UPLOADS_DIR` environment variable in container
- ❌ Environment-specific path resolution not working

### Technical Details

**Expected Behavior:**
```
Frontend POST: /api/uploads?env=dev
Backend lookup: /app/env/dev/uploads (mounted volume)
Container mount: ./env/dev/uploads:/app/env/dev/uploads
```

**Current Broken Behavior:**
```
Frontend POST: /api/uploads?env=dev
Backend lookup: /data/uploads (hardcoded fallback)
Container issue: /data/uploads directory doesn't exist
```

**Code Location:**
- File: `src_common/admin_routes.py`
- Function: `_uploads_dir(env: Optional[str] = None)`
- Line: `base = os.getenv("UPLOADS_DIR", "/data/uploads")`

## Reproduction Steps

1. Start the containerized monolithic app
2. Navigate to http://localhost:8000/admin/ingestion
3. Attempt to drag-and-drop a PDF file into the upload area
4. **Result:** Upload fails, no file appears in uploads list
5. Alternatively, click "Select PDF Files" button
6. Select a PDF file from file picker
7. **Result:** Upload fails, no file appears in uploads list

## Environment Details

**Container Setup:**
- Container: `ttrpg-app-dev`
- Image: `ttrpg_center-app`
- Port: 8000:8000
- Volume Mount: `./env/dev/uploads:/app/env/dev/uploads`

**Missing Configuration:**
- Environment variable `UPLOADS_DIR` not set in container
- Should be: `UPLOADS_DIR=/app/env/dev/uploads`

## Impact Assessment

**Business Impact:**

- Blocks testing of Gate 0, Pass A, Pass B pipeline
- Prevents validation of restored functionality

**User Experience:**

- Appears as if system is broken or unresponsive
- Forces users to manually copy files to uploads directory

## Fix Implementation Plan

### Phase 1: Container Environment Fix
```bash
# Stop current container
docker stop ttrpg-app-dev
docker rm ttrpg-app-dev

# Restart with correct environment variable
docker run -d --name ttrpg-app-dev \
  --network ttrpg-dev-network \
  -p 8000:8000 \
  --env-file ./env/dev/config/.env \
  -e TARGET_ENV=dev \
  -e SERVICE_NAME=app \
  -e PORT=8000 \
  -e UPLOADS_DIR=/app/env/dev/uploads \
  -v ./:/app \
  -v ./env/dev/logs:/app/env/dev/logs \
  -v ./env/dev/cache:/app/env/dev/cache \
  -v ./env/dev/uploads:/app/env/dev/uploads \
  --entrypoint="" ttrpg_center-app \
  uvicorn app:app --host 0.0.0.0 --port 8000
```

### Phase 2: Code Enhancement (Optional)
Update `_uploads_dir()` function to be more environment-aware:
```python
def _uploads_dir(env: Optional[str] = None) -> str:
    if env:
        # Use environment-specific directory
        base = f"/app/env/{env}/uploads"
    else:
        # Fall back to environment variable or default
        base = os.getenv("UPLOADS_DIR", "/data/uploads")
    os.makedirs(base, exist_ok=True)
    return base
```
